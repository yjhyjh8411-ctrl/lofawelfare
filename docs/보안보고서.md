## 1. 시스템 개요 (쉽게 말하면?)

이 시스템은 직원들이 복지 혜택을 신청하고, 담당자가 처리하는 **웹 프로그램**입니다.

쉽게 비유하면:
> 🏫 학교 급식 신청 게시판과 비슷합니다.
> 학생(직원)이 신청서를 내면, 선생님(관리자)이 확인하고 승인하는 구조입니다.

---

## 2. 데이터는 어디에 저장되나요?

### ✅ Google Firebase (구글 클라우드)에 저장됩니다

| 항목 | 내용 |
|------|------|
| 서비스명 | Google Firebase (Firestore) |
| 운영사 | Google LLC (미국) |
| 데이터 위치 | 서울 리전 (asia-northeast3) |
| 보안 인증 | ISO 27001, SOC 2/3, FedRAMP |
| 주소 | `lofawelfare-3ae73.firebasestorage.app` |

### 쉽게 설명하면?
> 📦 구글 드라이브처럼, 데이터가 구글의 초대형 금고에 저장됩니다.
> 이 금고는 한국(서울) 데이터센터에 있으며, 구글이 24시간 365일 보안을 관리합니다.

---

## 3. 로그인은 어떻게 되나요? (인증 방식)

### Firebase Authentication 사용
- 직원 ID: **사번@lofa.local** 형식 (예: `2121@lofa.local`)
- 비밀번호: 암호화된 형태로 저장 (평문 저장 없음)
- 구글의 인증 인프라가 로그인을 처리

### 쉽게 설명하면?
> 🔑 아파트 비밀번호처럼, 본인만 아는 번호로 들어옵니다.
> 비밀번호 자체는 암호화되어 저장되므로, 관리자도 알 수 없습니다.
> 관리자는 비밀번호를 **초기화**만 할 수 있습니다.

---

## 4. 외부에서 데이터를 가져갈 수 있나요? (접근 제어)

### Firestore 보안 규칙 적용
```
- 로그인한 사람만 데이터 접근 가능
- 본인 신청 내역만 볼 수 있음
- 관리자만 전체 데이터 열람/수정 가능
- 미로그인 상태에서는 아무것도 볼 수 없음
```

### 쉽게 설명하면?
> 🚪 아파트 공동현관처럼, 비밀번호를 모르면 아예 들어올 수 없습니다.
> 들어와도 자기 집(자기 데이터)만 볼 수 있고, 관리자(경비원)만 전체를 볼 수 있습니다.

---

## 5. 네트워크 전송 중 도청되지 않나요?

### HTTPS (TLS) 암호화 적용
- 모든 통신은 HTTPS(암호화된 연결)로 처리됨
- Firebase Hosting이 자동으로 SSL 인증서 관리
- HTTP → HTTPS 자동 리다이렉트

### 쉽게 설명하면?
> 📬 일반 편지 대신 봉인된 특수 봉투(HTTPS)를 사용합니다.
> 중간에 누가 가로채도 내용을 읽을 수 없습니다.

---

### 질문: 관리자가 직원 비밀번호를 바꿀 수 있는데 괜찮나요?

**결론: 문제없음 ✅**

| 항목 | 내용 |
|------|------|
| 처리 방식 | 서버 측 전용 (클라이언트 노출 없음) |
| 권한 제한 | 관리자 계정만 가능 |
| 감사 가능 | Firebase Console 로그로 확인 가능 |
| 일반 기업 관행 | 대부분의 기업 시스템에서 IT 관리자 초기화 기능 운영 |

### 쉽게 설명하면?
> 🏢 회사 IT팀이 직원 컴퓨터 비밀번호를 초기화해주는 것과 같습니다.
> 관리자가 비밀번호를 보거나 알게 되는 게 아니라, 새 비밀번호로 교체만 합니다.

## 7. 구글 클라우드를 못 쓰는 환경이면?

일부 회사 방화벽에서 구글 서비스가 차단될 수 있습니다.

### 확인 방법
1. `firebase.google.com` 접속 테스트
2. `lofawelfare-3ae73.firebaseapp.com` 접속 테스트

### 만약 차단된다면 대안
- **Firebase 허용 도메인 화이트리스트 요청 (권장)** — 정보화팀에 아래 도메인 허용 요청
  - `*.firebaseapp.com, *.web.app, *.googleapis.com`
- VPN을 통한 접속

> ⚠️ **온프레미스(사내 서버) 전환은 Firebase와 무관한 별개 선택지입니다.**
> 온프레미스로 전환하면 Firebase(데이터베이스·인증·호스팅) 전체를 자체 서버로 교체해야 하므로 시스템 전면 재개발이 필요합니다. 이는 현실적으로 비용과 시간이 크게 소요되므로 권장하지 않습니다.
> **현재 시스템은 Firebase를 기반으로 하므로, 방화벽 문제는 화이트리스트 등록으로 해결하는 것이 최선입니다.**
