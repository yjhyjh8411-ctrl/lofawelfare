# LOFA 복지시스템 보안체계 발표자료

**한국지방재정공제회 사내근로복지기금 신청 시스템**
2026년 3월

---

## 1. 시스템 보안 개요

LOFA 복지시스템은 **Firebase** 플랫폼을 기반으로 구축되어 있으며,
Google Cloud의 엔터프라이즈급 보안 인프라 위에서 운영됩니다.

쉽게 말해, **Google이 보안을 책임지는 클라우드 위에 우리 시스템이 올라가 있다**고 이해하시면 됩니다.

---

## 2. 인증(로그인) 보안

### 어떻게 보호하나요?

**Firebase Authentication**이 로그인을 관리합니다.

| 항목 | 설명 |
|------|------|
| 비밀번호 저장 | 비밀번호는 **해시(암호화)** 처리되어 저장됩니다. 관리자도 원본 비밀번호를 볼 수 없습니다. |
| 로그인 방식 | 이메일/비밀번호 + Google OAuth 2.0 (이중 로그인 방식 지원) |
| 세션 관리 | 로그인 후 발급되는 **토큰(Token)**으로 본인 확인. 토큰은 자동 만료됩니다. |
| Google 로그인 | Google의 OAuth 2.0 프로토콜 사용 -- 비밀번호가 우리 서버를 거치지 않습니다. |

### 쉽게 비유하면?
- 비밀번호 해시 = 자물쇠의 열쇠 모양만 기록하고, 실제 열쇠는 버리는 것
- 토큰 = 놀이공원 입장팔찌. 한번 발급받으면 매번 신분증 안 꺼내도 됨. 하루 지나면 자동 만료.

### Firebase Console에서 확인 가능한 부분
```
Firebase Console > Authentication > Users 탭
- 각 사용자의 UID, 이메일, 로그인 제공업체, 생성일, 마지막 로그인 확인 가능
- 비밀번호는 해시되어 있어 관리자도 조회 불가
- "비밀번호 재설정" 기능으로만 초기화 가능
```

## 3. 데이터베이스 보안

### Firestore 보안 규칙

Firestore는 **보안 규칙(Security Rules)**으로 데이터 접근을 통제합니다.

```
Firebase Console > Firestore Database > 규칙 탭
```

### 어떻게 작동하나요?

| 규칙 | 의미 |
|------|------|
| 로그인한 사용자만 | 로그인하지 않으면 데이터를 읽을 수도, 쓸 수도 없습니다 |
| 본인 데이터만 수정 | 다른 사람의 신청서를 수정하거나 삭제할 수 없습니다 |
| 관리자 전용 기능 | 관리자 권한이 있는 계정만 직원 관리, 신청서 승인 등이 가능합니다 |

### 쉽게 비유하면?
- 보안 규칙 = 건물의 **출입카드 시스템**
  - 1층(공개 데이터): 누구나 출입 가능
  - 내 사무실(내 신청서): 내 카드로만 출입
  - 관리자 방(관리 기능): 관리자 카드만 출입 가능

### Firebase Console에서 확인 가능한 부분
```
Firebase Console > Firestore Database > 데이터 탭
- 컬렉션 구조 확인: users, applications, form_configs, budget_groups 등
- 각 문서의 필드와 값 확인 가능

Firebase Console > Firestore Database > 규칙 탭
- 현재 적용된 보안 규칙 코드 확인
- 규칙 수정 및 게시 가능
```

## 4. 개인정보 암호화

### 민감한 데이터는 어떻게 보호하나요?

시스템에서 **개인정보 암호화** 옵션이 켜진 필드는 AES-256 암호화되어 저장됩니다.

| 단계 | 설명 |
|------|------|
| 신청서 제출 시 | 민감 필드 데이터를 **AES-256으로 암호화** 후 저장 |
| 관리자 조회 시 | 암호화된 데이터를 **복호화**하여 표시 |
| DB에 저장된 형태 | 원본이 아닌 **암호문(알아볼 수 없는 문자열)**으로 저장 |

### AES-256이란?
- 미국 정부가 기밀 문서를 보호할 때 사용하는 암호화 표준
- 256비트 키 = 가능한 조합이 2의 256승 (사실상 해독 불가능)

### 쉽게 비유하면?
- 암호화 = 편지를 **금고에 넣고 잠그는 것**
- 복호화 = 올바른 열쇠로 **금고를 여는 것**
- AES-256 = 열쇠 조합이 우주의 원자 수보다 많은 금고

### Firebase Console에서 확인 가능한 부분
```
Firebase Console > Firestore Database > 데이터 탭 > applications 컬렉션
- 암호화된 필드: 실제 값 대신 "U2FsdGVkX1..." 같은 암호문이 저장됨
- 암호화되지 않은 필드: 원본 텍스트 그대로 저장됨
- 비교해보면 암호화 적용 여부를 눈으로 확인 가능
```

## 5. 파일 저장소 보안

### 첨부파일은 어떻게 보호하나요?

첨부파일(증빙서류 등)은 **Firebase Storage**에 저장됩니다.

| 항목 | 설명 |
|------|------|
| 저장 위치 | Google Cloud Storage (Google 데이터센터) |
| 전송 암호화 | HTTPS(TLS 1.2+)로 전송 -- 중간에 가로채도 읽을 수 없음 |
| 저장 암호화 | Google이 자동으로 저장된 파일을 암호화 (AES-256) |
| 접근 제어 | Storage 보안 규칙으로 본인 파일만 접근 가능 |
| 파일 경로 | `applications/[사용자ID]/[사번_이름_부서_항목_시간_파일명]` |

### 쉽게 비유하면?
- HTTPS = 편지를 **밀봉된 봉투**에 넣어 보내는 것 (배달원이 읽을 수 없음)
- Storage 암호화 = 서류를 **잠긴 캐비넷**에 보관하는 것

### Firebase Console에서 확인 가능한 부분
```
Firebase Console > Storage > Files 탭
- applications/ 폴더 구조 확인
- 각 사용자별 폴더에 첨부파일 저장
- 파일 URL, 크기, 생성일 확인 가능

Firebase Console > Storage > Rules 탭
- 파일 접근 보안 규칙 확인
```

## 6. API 보안 (서버 통신)

### 서버와 어떻게 안전하게 통신하나요?

| 항목 | 설명 |
|------|------|
| 통신 방식 | 모든 API 호출은 **HTTPS** 사용 (암호화된 채널) |
| 인증 토큰 | API 호출 시 Firebase 인증 토큰 첨부 -- 토큰 없으면 거부 |
| 서버 측 검증 | Firebase Admin SDK로 토큰 유효성 재검증 |
| 관리자 API | 관리자 권한 추가 확인 후 실행 |

### 주요 보안 API 목록

| API | 기능 | 보호 수준 |
|-----|------|-----------|
| /api/reset-password | 비밀번호 초기화 | 관리자 전용 |
| /api/delete-user | 사용자 삭제 | 관리자 전용 |
| /api/update-email | 이메일 변경 | 관리자 전용 |
| /api/encrypt | 데이터 암호화 | 인증 필요 |
| /api/decrypt | 데이터 복호화 | 인증 필요 |

### 쉽게 비유하면?
- API 보안 = 은행 창구 시스템
  - 신분증(토큰) 없으면 창구 접근 불가
  - 일반 고객(직원)은 본인 업무만 가능
  - 지점장(관리자)만 특수 업무 처리 가능

## 7. 호스팅 및 네트워크 보안

### 시스템은 어디에서 운영되나요?

| 항목 | 설명 |
|------|------|
| 호스팅 | Firebase Hosting + Cloud Functions (Google Cloud) |
| SSL/TLS | 자동 HTTPS 인증서 발급 및 갱신 (Let's Encrypt) |
| CDN | Google의 글로벌 CDN으로 빠르고 안전한 콘텐츠 전송 |
| DDoS 방어 | Google Cloud의 자동 DDoS 방어 시스템 적용 |
| 서버 위치 | us-central1 (미국 중부) -- Google Cloud 데이터센터 |

### 쉽게 비유하면?
- Firebase Hosting = Google이 운영하는 **초대형 보안 빌딩**에 우리 사무실을 임대한 것
- SSL = 건물 출입구에 **보안 검색대**가 설치된 것
- CDN = 전국 곳곳에 **지점**을 두어 가까운 곳에서 빠르게 서비스
- DDoS 방어 = 건물 앞에 **경비원**이 수상한 방문객을 걸러내는 것

## 10. 자주 묻는 보안 질문

**Q. 해커가 데이터베이스를 직접 접근할 수 있나요?**
A. 아닙니다. Firestore 보안 규칙이 모든 접근을 통제합니다. 로그인하지 않은 사용자는 데이터를 읽을 수도 쓸 수도 없습니다.

**Q. 비밀번호가 유출되면 어떻게 되나요?**
A. 비밀번호는 해시 처리되어 저장되므로, DB가 유출되어도 원본 비밀번호를 알아낼 수 없습니다. 관리자가 즉시 비밀번호를 초기화할 수 있습니다.

**Q. 다른 직원의 신청서를 볼 수 있나요?**
A. 일반 직원은 본인의 신청서만 볼 수 있습니다. 관리자만 전체 신청서를 조회할 수 있습니다.

**Q. 첨부파일이 안전한가요?**
A. 첨부파일은 Google Cloud Storage에 암호화되어 저장되며, 보안 규칙으로 접근이 통제됩니다.

**Q. Google Cloud가 안전한가요?**
A. Google Cloud는 ISO 27001, SOC 2/3, GDPR 등 국제 보안 인증을 보유하고 있으며, 전 세계 주요 기업과 정부기관이 사용하고 있습니다.
