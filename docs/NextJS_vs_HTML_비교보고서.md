# Next.js 프로젝트 vs 일반 HTML 프로젝트 비교 보고서

**한국지방재정공제회 복지신청 시스템**
작성일: 2026년 3월

---

## 한 줄 요약

> **HTML** = 정적인 종이 신문 📰 | **Next.js** = 살아있는 앱 📱

---

## 1. 핵심 차이점 비교

| 구분 | 일반 HTML | Next.js |
|------|-----------|---------|
| **개발 방식** | 파일 하나씩 직접 작성 | 컴포넌트 조합 방식 |
| **페이지 이동** | 전체 화면 새로 불러옴 | 필요한 부분만 교체 |
| **데이터 처리** | 직접 백엔드 서버 필요 | 내장 API 기능 포함 |
| **로그인/인증** | 구현 복잡 | Firebase Auth 연동 쉬움 |
| **속도 (체감)** | 페이지마다 느릴 수 있음 | 빠름 (SPA 방식) |
| **배포** | FTP 업로드 등 | Firebase Hosting 자동 |
| **유지보수** | 반복 코드 많음 | 공통 컴포넌트 재사용 |
| **보안 처리** | 직접 구현해야 함 | 서버 컴포넌트로 분리 |

---

## 2. 쉬운 비유로 이해하기

### HTML = 종이 카탈로그 📖
- 한번 인쇄된 내용은 바뀌지 않음
- 페이지를 넘기면 처음부터 다시 읽어야 함
- 만들기 쉽지만 기능 추가가 어려움

### Next.js = 스마트폰 앱 📱
- 화면 일부만 업데이트 가능
- 로그인 상태 유지
- 카카오뱅크 앱처럼 빠르고 동적

---

## 3. 우리 시스템에 Next.js를 선택한 이유

### 3.1 로그인/인증이 필요함
```
HTML: 로그인 구현을 위해 별도 서버 언어(PHP, Python 등) 필요
Next.js: Firebase Auth를 5줄 코드로 연동 가능
```

### 3.2 데이터가 실시간으로 변해야 함
```
HTML: 새로고침해야만 최신 신청 상태 확인 가능
Next.js: Firestore 리스너로 실시간 업데이트 가능
```

### 3.3 관리자 페이지가 복잡함
```
HTML: 탭, 모달, 검색 등 구현이 매우 복잡
Next.js: React 컴포넌트로 깔끔하게 구현
```

### 3.4 API(서버 기능)가 필요함
```
필요한 서버 기능:
- 비밀번호 초기화 (/api/reset-password)
- 직원 삭제 (/api/delete-user)
- Excel 다운로드 (/api/excel)
- 데이터 마이그레이션 (/api/migrate-project)

HTML: 이런 기능을 위해 별도 서버(PHP/Python/Node.js) 필요
Next.js: 같은 프로젝트 안에 API Route로 포함 가능
```

## 4. Next.js의 추가 장점

### 4.1 한 번에 관리
```
HTML 방식:
├── index.html
├── admin.html
├── my-status.html
└── server.py  ← 별도 백엔드 서버
    └── 배포 서버 별도 관리 필요

Next.js 방식:
└── lofawelfare/
    ├── src/app/  ← 프론트엔드
    ├── src/api/  ← 백엔드 API
    └── Firebase Hosting으로 한 번에 배포
```

### 4.2 TypeScript 지원 (코드 안전성)
- 변수 타입을 미리 정해서 실수 방지
- HTML+JS는 실행해봐야 오류 발견
- Next.js+TypeScript는 코드 작성 중에 오류 표시

### 4.3 SEO 및 성능 최적화
- 정적 생성(Static Generation)으로 빠른 로딩
- 이미지 자동 최적화
- 코드 자동 분할(Code Splitting)

## 5. Next.js의 단점 (솔직한 평가)

| 단점 | 설명 | 우리 시스템 영향 |
|------|------|----------------|
| 학습 곡선 | 순수 HTML보다 배우기 어려움 | 외부 개발자 유지보수 필요 |
| 빌드 필요 | 코드 수정 후 빌드 과정 필요 | 배포 시 수분 소요 |
| 노드 환경 | Node.js 환경 필요 | 서버 설정 필요 |
| 무거운 번들 | 초기 로딩 파일 크기가 큼 | 첫 접속 시 약간 느릴 수 있음 |

## 6. 언제 HTML이 더 나을까?

| 상황 | 추천 |
|------|------|
| 단순 정보 소개 페이지 | HTML |
| 로그인 없는 정적 사이트 | HTML |
| 개발자 없이 직접 수정 | HTML |
| 동적 기능 + 로그인 필요 | **Next.js** ✅ |
| 관리자 기능 + API 필요 | **Next.js** ✅ |
| Firebase 연동 | **Next.js** ✅ |

---

## 7. 결론

우리 복지신청 시스템은 **로그인, 데이터 CRUD, 관리자 기능, API** 등이 모두 필요하기 때문에 Next.js가 최적입니다.

> HTML로 같은 기능을 구현하려면 PHP/Python 백엔드 서버를 따로 구축하고, 더 많은 코드를 작성해야 하며, 유지보수도 복잡해집니다.

**Next.js = HTML + CSS + JavaScript + 백엔드 API + 보안 + 최적화**를 하나의 프레임워크로 처리하는 현대적 방식입니다.
